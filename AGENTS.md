# ChangeRail — инструкции репозитория

Этот публичный репозиторий владеет общим native runtime, адаптерами, тестами,
установкой и документацией. Единственный актуальный lifecycle: `openspec-v1`,
одна карточка и один OpenSpec change, максимум два независимых ревью с общим
остатком для repair; время является наблюдением.

Работайте в основном checkout, сохраняйте посторонние изменения. Правка через
ссылку проекта меняет этот репозиторий; проверяйте его `git status` отдельно.
Исправления инструмента и продукта имеют разных владельцев и отдельные коммиты.
Делегируйте независимые ограниченные задачи без пересечения записей.

Ядро — `scripts/changerail/`, схемы, skills и общие тесты — `tools/changerail/`,
pinned OpenSpec — `tools/openspec/`. Профиль потребителя, board, evidence,
credentials и журналы остаются у потребителя. Linux — текущая платформа.
Не возвращайте старые FF/offline/Windows исполнительные маршруты.

Тесты запускаются при разработке инструмента, не при каждой установке runtime.
Для исправления используйте регрессию; для изменения подключения — тесты ссылок,
изоляции проектов и восстановления. Полный набор принадлежит CI ChangeRail.
Остановленный оператором набор не перезапускайте.

```sh
python3 -m pip install -e '.[test]'
./bin/test-changerail
python3 -m ruff check scripts tools/changerail/tests distribution.py
git diff --check
```

Общий исходник доступен подключённым проектам сразу. Уже запущенный процесс
не подхватывает изменения Python автоматически. Для продолжения остановленного
run используйте документированный repair receipt, не меняйте исходный run.json
и не обнуляйте review/evidence accounting.

Пишите общую документацию по-русски; wire identifiers и agent skills могут быть
английскими. Примеры используют произвольный каталог инструмента и generic
проекты. Не переносите профили продуктов в публичные defaults.

Не публикуйте `.runtime/`, `internal/`, provider/auth настройки, credentials,
журналы, зависимости и клиентские данные. Локальный `.codex/config.toml` не входит
в публичную выборку; его пользовательские значения сохраняются локально.
Перед публикацией проверяйте будущую Git-выборку, архив и достижимую историю.
Публикация и release tag — отдельные действия после проверки результата.

Старое дерево сохранено в Git-истории. Актуальные контракты — README,
DISTRIBUTION.md и docs/. Исторические release scripts не являются текущими gates.
