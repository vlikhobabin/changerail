# Единый локальный runtime ChangeRail

Этот репозиторий — общий исходник native runtime. Версия кандидата `2.0.0-rc.1`
объединяет lifecycle OpenSpec, проверяемые доказательства, независимое ревью и
возобновление доставки. Это предварительная версия для испытаний перед стабильным выпуском 2.0.0.

Проект может установить runtime-копию или подключить этот checkout через
явные симлинки. Во втором режиме правка общего файла сразу доступна новым
процессам всех подключённых проектов. Корень инструмента и корень проекта
разделены; профиль, board, Git-операции и evidence остаются у потребителя.
Разработчик подключает общий код и тесты; обычный потребитель — только runtime.
См. [подключение](docs/shared-source.md), [разработку](CONTRIBUTING.md) и
[миграцию](docs/migration.md).

## Контракт

- Новое исполнение: только `openspec-v1`, одна карточка и один native change.
- OpenSpec владеет proposal, delta specs, design и tasks. Runner владеет
  сессиями, board, evidence, review, archive, финальными проверками и публикацией.
- Время и размер — наблюдения. Максимум два независимых ревью, включая ремонт
  после NO-GO и неудачной финальной проверки. Продолжение после archive остаётся
  в том же цикле и потоке ревью; resume не обнуляет счётчики.
- Старые записи доступны только для чтения. Установка нового runtime не даёт
  права продолжать старый frozen run по изменённому контракту.
- У каждого критерия приёмки есть ID и план evidence: предусловие, действие,
  ожидаемый результат, метод и этап проверки. Доказательства связываются с
  фактическими байтами, результатом команды, ролью и текущим payload.
- Неизменённую неудачную или прерванную проверку нельзя автоматически повторять.
  Незавершённая попытка и конкурирующий проверяющий блокируют новое исполнение.
- По умолчанию потерявшие актуальность проверки исполняются повторно.
  Переиспользование включается явно для локальных детерминированных проверок
  с полным объявленным набором зависимостей. Runtime и изменяемые внешние
  сервисы этим механизмом не доказываются.

## Границы

`scripts/changerail/` содержит одинаковое ядро во всех проектах.
`openspec_adapter.py` и native workflow связывают его с локальным OpenSpec;
`adapters/codex.py` строит вызов локального CLI, `adapters/pytest.py` проверяет
результаты конкретных тестов. Runtime evidence использует типизированные
ссылки на target, session, authorization, preflight и recovery; проект задаёт
требования к этим наблюдениям в плане evidence и своих инструкциях.

Профиль задаёт команды проверок, model routes, локальный launcher и проектную
политику. Доменные команды и credentials не входят в ядро. Новые форматы тестовых
результатов добавляются адаптерами с общими проверками ownership/freshness,
а не копированием и изменением runner в каждом проекте.

## Установка и обновление

Интерфейс сборки, проверки, первичного принятия исходников и установки:

```sh
python3 distribution.py --help
```

Первичное принятие существующего форка требует явного списка заменяемых файлов
и их хешей. Последующие обновления проверяют установленный lock и отказывают
при локальном изменении ядра. Проектные настройки и посторонние файлы сохраняются.
Незавершённый запуск требует отдельного решения о сохранении его как истории;
проверка установки не переписывает run receipts и не выдаёт право на resume.

Начальный профиль и карточка находятся в `templates/`. Команды проверок нужно
заменить на реальные команды проекта до первой доставки. Требуются Python 3.11+,
Git, jsonschema, локальный Codex launcher и Node.js, совместимый с закреплённым
OpenSpec 1.3.1. Установка зависимостей OpenSpec выполняется явно; обычные команды
не скачивают пакеты и не используют глобальный fallback.

## Проверка изменений runtime

Тесты инструмента находятся только здесь, в `tools/changerail/tests/` исходника.
Тесты, OpenSpec wrapper self-tests, фикстуры и `bin/test-changerail` не входят
в устанавливаемый архив. Проекты используют runtime; их CI не запускает тесты
ChangeRail. Установка проверяется по хешам и командой `./bin/chrl wiring`.
Интеграционные сценарии используют временные Git-репозитории,
локальный OpenSpec и подставленные ответы модели. Это не доказательство реальной
модельной доставки или поведения конкретного runtime-провайдера.

Исправление делается в этом общем исходнике, в том числе через ссылку потребителя,
и проверяется затронутой регрессией. Подключённые проекты сразу видят новую версию;
для runtime-копий собирается и устанавливается новый архив.
До публикации происхождение кандидата указывается как working-source
snapshot с точными хешами; release tag этим не имитируется.
