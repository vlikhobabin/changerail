# ChangeRail 2.0.0-rc.3

Предварительный выпуск с точным восстановлением принятого плана после изменения
`Next` реализацией. Тег — `v2.0.0-rc.3`, Python metadata — `2.0.0rc3`.
[Страница выпуска](https://github.com/vlikhobabin/changerail/releases/tag/v2.0.0-rc.3)
содержит release commit, завершённый CI и файлы дистрибутива.

## Поведение

Раньше возврат принятого Next вручную устранял plan drift, но нарушал точный
retained manifest. Неудачный resume мог дополнительно оставить child без
`native-plan.json`. Новый `plan-restore-prepare` проверяет исходный accepted plan,
полную ancestry и payload, а `plan-restore-apply --authorize <sha256>` восстанавливает
только принятые байты Next. Proposal, intent и effective manifest хранятся отдельно;
старые runs не меняются и не дополняются файлами. Failed child остаётся предком.

Обычный resume использует applied receipt для единственного successor, сохраняет
завершённые группы и израсходованные ревью. После восстановления требуются свежие
focused/observed proofs. Последующие sync, handoff, review, archive, final и
publication проходят штатно. Успешный apply сам по себе не означает доставку.

Новые admissions сохраняют accepted-card snapshot. Native implementing skill
фиксирует запрет правки Next/Scope/Acceptance и ложного completion при отказе
handoff. Runbooks описывают prepare, apply, согласование прерываний и resume.

## Совместимость и границы

Linux, Python 3.11+, Node.js >=20.19.0, pinned OpenSpec 1.3.1; одна карточка,
один native change и максимум два независимых ревью с общим остатком для repair.

Новый runtime можно использовать как координатор с `--project` и
`--runtime-archive` для установленного native predecessor `2.0.0-candidate.5`,
`2.0.0-rc.1` или `2.0.0-rc.2`. Переход требует известных schemas/identity shapes,
проверенного полного frozen distribution lock, точного старого payload из
compatibility descriptor и target archive, точно совпадающего
с выполняемым runtime. Профиль, launcher и адаптеры потребителя сохраняются.
Неизвестные identities, локальный drift, несвязанные frozen runs и read-only
история не получают права исполнения. Это отдельная операция; обычный install
не разрешает продолжение старого run.

Изменились runtime и agent skill, поэтому обычный resume по прежней frozen identity
может быть запрещён. Shared-source Python runtime-repair сохраняет прежнюю раннюю
границу применимости; произвольная миграция позднего shared-source run не добавлена.

Plan restoration не покрывает остановку оператором, unresolved verification,
pending provisional review, archive, final floor и publication. После исчерпания
двух ревью prepare отклоняется. Посторонние ошибки board и неверный handoff
по-прежнему блокируют доставку. Реальные runs потребителей этим выпуском не
переписываются и автоматически не продолжаются.

## Проверки и файлы

Локальные адресные регрессии проверяют exact Next, сохранность истории,
неудачного child, accounting, обновление evidence и interrupted apply/installation.
Синтетические fixtures используют временные проекты и архивы без потребительских
данных. Сквозной тест с контролируемым model launcher и явным разрешением
синтетического старого комплекта только внутри теста прошёл от installed
predecessor через prepare/apply/resume до stock archive, final floor и commit/push
в локальный bare remote; исходная история сохранилась, израсходовано одно ревью.
Полный CI точного release commit выполняется на Python 3.11 и 3.12;
ссылка и итоговые результаты добавляются на страницу выпуска после завершения.

Архив — `changerail-2.0.0-rc.3-runtime.tar.gz`; дополнения — `SHA256SUMS` и
`release-provenance.json` с точными source commit/tree и хешами. Исторический
`upstream_commit` внутри комплекта не изменён.
