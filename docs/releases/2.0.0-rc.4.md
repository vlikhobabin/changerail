# ChangeRail 2.0.0-rc.4

Предварительный выпуск линии 2.0.0. Тег — `v2.0.0-rc.4`, Python metadata —
`2.0.0rc4`. Статус stable не заявлен.
[Страница выпуска](https://github.com/vlikhobabin/changerail/releases/tag/v2.0.0-rc.4)
содержит точный commit, завершённый CI и assets.

## Что изменилось

Self-host разработка отделяет изменяемый исходник продукта от исполняющего его
immutable engine. Snapshot имеет собственные inventory и identity; команды
создания, проверки, bind и явного rebind проверяют байты и сохраняют receipts.
Изменение Python в dev не меняет уже загруженный процесс.

`self-host-recovery-prepare` фиксирует точный corrective diff, принятый план,
engine и project inputs. `apply` резервирует единственного successor, атомарно
сохраняет его состояние и dispatch. `reconcile` проверяет сохранённый переход
без запуска writer. Повторный apply возвращает тот же successor после dispatch.
Predecessor и ancestry остаются неизменными; completed groups не выполняются
заново, evidence и использованные независимые ревью входят в общий accounting.

Продолжение поддерживает классифицированный технический сбой модели и
проверенную self-host финализацию. После commit bound successor может пройти
точный обычный resume при совпадении сохранённой identity. Неизвестный сбой,
семантический NO-GO, живой процесс, конфликт writer и несогласованный payload
не получают разрешения на техническое восстановление.

Инструкции recovery/finalize теперь требуют прочитать конкретный objective из
контекста, завершить Result/Log до актуальных receipts и записать observed proofs
всех назначенных implementation conditions. Успешный `chrl evidence` сам по себе
не доказывает критерий. Исправимые пропуски proofs завершаются перед handoff.

Dev checkout, рабочий checkout релиза, engine snapshot и consumer binding имеют
разные роли. Публикация релиза не переключает consumers и не меняет snapshots.
Установка нового выпуска не даёт старой read-only истории права resume;
self-host receipt не заменяет receipt обычного runtime repair или plan restoration.
Не редактируйте `run.json`, manifests или review/evidence accounting ради обновления.

## Проверка

До подготовки выпуска сохранён полный локальный результат: **1010 passed**,
strict OpenSpec validation прошла. Реальный self-host run завершил finalize,
ровно два независимых ревью, archive, финальную проверку и publication; повторные
apply/reconcile вернули того же terminal successor, completed groups не повторялись.
Эти наблюдения не означают проверку всех внешних runtime-провайдеров.

В этом релизном изменении обновлены версия и документация; код runtime и тесты
совпадают с опубликованной доставкой и последующим уточнением docstrings.
Полный CI точного release commit обязателен на Python 3.11 и 3.12, включая
OpenSpec wrapper, Ruff, public-surface scan и diff. Локальные проверки выпуска
охватывают установщик, согласованность версии, ссылки, воспроизводимость архива
и соответствие файлов/modes Git. ChangeRail suite в consumers не запускается.

Архив — `changerail-2.0.0-rc.4-runtime.tar.gz`. Внутри находится manifest с
пофайловыми SHA-256; рядом публикуются `SHA256SUMS` и `release-provenance.json`
с точными source commit/tree и hash payload. Исторический `upstream_commit`
в `distribution.json` не является release commit.

## Ограничения

Linux — текущая платформа. Snapshot нельзя обновлять на месте. Rebind не
откатывает run или accounting. Установщик сохраняет before/audit и выполняет
rollback перехваченной ошибки, но не имеет общей команды автоматического
reconcile после SIGKILL. `detach` требует неизменного inventory runs после attach.
В `2.0.0-rc.4` Git мог предупреждать о ссылочном `tools/openspec/.gitignore`;
после выпуска этот файл исключён из payload и из shared-source ссылок (см.
[shared-source.md](../shared-source.md)), а исключения зависимостей потребитель
держит в корневом `.gitignore` или `.git/info/exclude`.
