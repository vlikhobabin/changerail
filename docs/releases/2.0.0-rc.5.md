# ChangeRail 2.0.0-rc.5

Кандидат предварительного выпуска линии 2.0.0. Планируемый тег — `v2.0.0-rc.5`,
Python metadata — `2.0.0rc5`. Подготовка этих notes не означает завершения CI,
публикации или переключения локальных executors.

## Executor из отдельного релиза

Dev-проект и исполнитель размещаются в разных каталогах. Executor — полный
Git checkout принятого релиза с проверенной source/dependency identity.
Проектные launchers `.changerail/chrl` и `.changerail/openspec` выбирают runtime,
schemas, skills и зависимости релиза; проверки продукта используют dev-код
и его окружение. Настройки модели, board и evidence остаются у проекта.

`chrl-dist release-update prepare/apply/reconcile` обслуживает executor через
сохранённый proposal и пооперационный журнал. Provisioning зависимостей выполняют
явно под `provision-lease`. Apply/reconcile запускают отдельным coordinator вне
обновляемого дерева. `chrl-dist executor-bind prepare/apply/reconcile` сохраняет
before/after binding, launchers и inventory истории проекта.

Переключение действует только для будущих запусков: старые runs, receipts,
completed groups и review/evidence accounting не переписываются, successor
не создаётся. Новый executor не даёт старым frozen engines права resume при
изменённой identity и не расширяет allowance двух независимых ревью.

Порядок первоначального принятия и последующих обновлений — в
[runbook двух каталогов](../working-checkout.md#executor-из-релиза-два-каталога).
Первое получение реализации требует проверки опубликованных assets и точного
release commit; прежний executor не получает новый protocol от одного receipt.

## Совокупные test proofs и вызываемые helpers

Основной test `method.target` сохраняется. Необязательные `additional_targets`
добавляют обязательные цели проверки: каждую покрывает отдельный singleton
proof record. Совокупность records подтверждает условие; один реальный receipt
может поддерживать несколько релевантных условий отдельными condition-bound
records. Дублировать тесты или запускать их повторно ради номера условия не нужно.

Содержательные assertions могут оставаться во внешнем вызываемом helper.
`assertion_support.source` закрепляет входной файл теста, `invocation` — вызов,
а внешние fragments — точные исходные bytes. Reviewer проверяет путь вызова
и смысл assertions; валидатор сохраняет проверки identity, freshness и selection
фактически PASSED nodes. Старый или ошибочный proof не компенсируется хорошим.

Прежние singleton proofs поддерживаются. Для новых полей необходим совместимый
engine **до принятия плана**. `v2.0.0-rc.4` их не поддерживает: для него сохраняют
прежний singleton method. Обновление документации или binding не меняет принятый
Verify и frozen историю. Подробности — в [руководстве оператора](../operations.md#доказательства-результата-и-замена-engine).

## Дистрибутив и проверка

Сохранено исправление после rc.4: `tools/openspec/.gitignore` не входит в runtime
payload и source-link inventory. Исключения `node_modules` и других зависимостей
потребитель задаёт в корневом `.gitignore` или `.git/info/exclude`.

Локальная проверка кандидата охватывает затронутые границы executor/proof,
установку, ссылки, изоляцию проектов и восстановление, а также Ruff, синтаксис
launchers, inventory и извлечённый архив. Её точный результат фиксируется отдельно;
эти notes не заявляют выполненный CI или реальную активацию. Полный CI точного
release commit на Python 3.11 и 3.12 остаётся обязательным этапом публикации.

Архив `changerail-2.0.0-rc.5-runtime.tar.gz` для публикации собирают заново из
проверенного CI commit. Рядом публикуют `SHA256SUMS` и `release-provenance.json`
с точными source commit/tree и hash архива. Исторический
`distribution.json.provenance.upstream_commit` сохраняет прежнее значение.
[Quickstart](../quickstart.md) описывает проверку assets перед установкой.

Расширение восстановления формулировок tasks и отдельное разрешение дополнительных
операторских ревью в этот кандидат не входят. Существующий контракт восстановления
принятого `Next` и совместимость старых runtime сохраняются. Linux — текущая платформа.
