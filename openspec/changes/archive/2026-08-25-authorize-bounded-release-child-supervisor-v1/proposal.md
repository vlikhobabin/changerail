## Why

Published rescue `rescue-release-process-supervisor-boundary` makes S the first
foundation in the replacement lineage, but a future implementation cannot be
created until one clean, published authorization source binds its exact scope.

## What Changes

- Publish one card-owned six-field `Investigation authorization` object that
  binds the published rescue to exactly
  `implement-bounded-release-child-supervisor-v1`, with ceiling `500` and
  protocol allowance `true`.
- Preserve reciprocal rescue/authorization/future-successor relations, the
  successor's exact two-field authorization reference and its `<=499` added
  production-LOC limit relative to the published authorization HEAD.
- Declare future S as the sole owner of the platform-neutral child protocol and
  POSIX hard stdout/stderr/report framing, process containment, deadline,
  TERM-KILL escalation, reap and subreaper cleanup.
- Exclude Git parsing, scheduler policy, Windows Job behavior, registry,
  baseline/CI activation and receipt ownership; keep S structurally dormant
  until exact published A3.
- Keep the authorization payload docs-only: production, test and runtime LOC
  remain `0`; successor card and implementation remain absent.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `changerail-release-ci`: add the separately publishable S authorization
  source and its exact ownership, dormancy and focused-proof boundary.

## Impact

Planning changes only the authorization board card and
`openspec/changes/authorize-bounded-release-child-supervisor-v1/`. Delivery
synchronizes the release-CI delta into the main specification and archives the
same-slug change. Production code, tests, workflows, schemas, CLIs, runtime
state, successor card, review and publication are unchanged.
