## Context

The published clean acceleration decision established a future H/I/R/A
lineage. The unpublished H and I implementation episodes subsequently exhausted
their single repair after independent reviews. The retained forensic summaries
identify incomplete end-to-end containment, prelaunch validation, deterministic
ownership proof and native Windows supervision. Those findings motivate a new
boundary, but neither implementation, diff, runtime evidence nor local identity
is public authority.

## Goals / Non-Goals

**Goals:**

- Supersede only future active H/I/R/A work with a clean supervisor-first order.
- Establish exact six-field authorization objects for S, H4, I3, W1, R3 and A3.
- Make S the shared platform-neutral child protocol and POSIX containment owner.
- Keep Git semantics, scheduler policy and Windows native control disjoint.
- Keep all canonical baseline/CI activation, parsed YAML ownership and
  receipt/manifest/review/publish/CI fingerprint equality exclusively in A3.
- Keep predecessor-wave production structurally dormant until exact A3
  publication and remote reachability.
- Require clean worktrees and remote-reachable publication before each next
  authorization wave.
- Keep all bounded successors ordinary/fresh Sol-high, one-repair-only, without
  credential, mutation, live or final-certification authority.

**Non-Goals:**

- Reuse or repair either exhausted implementation path.
- Run a history scan, full-release, live Windows operation or an executable
  successor while deciding this lineage.
- Give S semantic parsing/scheduling/Windows ownership, or let H4/I3/W1 create
  canonical CI policy/oracles, receipt, registry or release authority.
- Treat measured timing as correctness authority or final certification.

## Decisions

### 1. Historical H/I sources are one-successor-only

The published H and I authorization sources remain immutable history. Each
contains a one-successor object for its original successor only, so neither can
authorize S, H4, I3, W1, R3 or A3. The exhausted implementations remain
forensic-only. Their generic findings are boundary input, not accepted code,
test, report, receipt, review or publication evidence.

### 5. Pre-A3 production remains structurally dormant

Before exact A3 is published and remote-reachable, S/H4/I3/W1/R3 production
MUST NOT be imported or invoked by `run-release-baseline`, a workflow,
review/publish gate or receipt schema. No full-release/CI authority or evidence
can come from this predecessor wave. After A3 publication, only its exact
integration paths may activate the published S/H4/I3/W1/R3 components.

### 6. Repair, publication and final certification remain bounded

Every S/H4/I3/W1/R3/A3 authorization and successor uses `ordinary` risk with a
fresh Sol/`high` independent review. It has at most one scoped repair. A second
terminal failure is not retried in that lineage and instead requires a new
design decision; no flag permits credentials, mutation, live admission or final
certification.

Every authorization, implementation and later wave starts from the exact
published predecessor in a clean worktree. Publication order is S, parallel
H4/I3/W1, R3, A3, measured optimization from A3 telemetry, then separate final
certification. Optimization receives its own bounded authorization and timing
is observational. Only the final certification card is `critical` and receives
fresh Sol/`xhigh`; it may run only after all focused/static/receipt/native
Windows gates are green.

## Risks / Trade-offs

Splitting ownership introduces more publications and handoffs, but it removes
the failed coupling between lifecycle control and semantic policy. The shared S
protocol is an explicit wire boundary, so its authorization permits that narrow
protocol while all later owners consume it without redefining it.
