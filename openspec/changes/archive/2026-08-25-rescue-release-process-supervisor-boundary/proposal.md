## Why

The previous clean H/I implementation paths each exhausted their sole repair.
Their forensic findings show that platform-neutral process containment,
semantic scheduling, and native Windows ownership must be independently
bounded before release authority can be delivered.

## What Changes

- Supersede the active future H/I/R/A release-loop lineage with S first, then
  parallel H4/I3/W1, then R3 and A3.
- Bind six exact future authorization objects to this rescue decision and set
  independent LOC/protocol limits.
- Separate POSIX child supervision, Git history parsing, scheduler policy and
  native Windows Job Object handling into non-overlapping owners.
- Preserve old H/I authorization sources and failed implementation payloads as
  historical/forensic-only; they cannot authorize a replacement.
- Route every bounded successor ordinary/fresh Sol-high with one repair, then
  require a new design after repeated terminal failure. Reserve critical/Sol-xhigh
  only for separate final certification after measured optimization.

## Capabilities

### New Capabilities
- None.

### Modified Capabilities
- `changerail-release-ci`: replace the future clean acceleration lineage with
  a supervisor-first, cross-platform bounded release-process sequence.

## Impact

Only the board card and release-CI OpenSpec contract change. No executable,
test or runtime code is added, and no history, full-release or live Windows
operation is run.
