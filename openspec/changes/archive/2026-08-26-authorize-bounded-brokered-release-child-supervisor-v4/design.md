## Decisions

### 1. One source authorizes one exact implementation

The card and synchronized requirement carry exactly one ordered six-field
object binding the published decision to
`deliver-brokered-release-child-supervisor-v4`. The future implementation uses
only the exact two-field reference to this published authorization.

### 2. Authorization publishes boundaries, not behavior

This payload adds zero production/test/runtime LOC and leaves the successor
absent. Broker readiness, ownership, protocol, cleanup, fatal-death honesty and
proof requirements become admission conditions for the later implementation;
they are not exercised or claimed here.

### 3. One bounded correction replaces rescue proliferation

Future v4 may use one same-card repair only after its first Sol/high NO-GO and
must then receive one final Sol/high re-review. Any remaining blocker is
terminal. This authorization itself uses the ordinary docs-only review route.

- **Authority drift.** Exact objects, published source commit, future LOC base
  and reciprocal relations are validated mechanically.
