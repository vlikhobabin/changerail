## Decisions

### 1. Authorization shape is exact and singular

The card/spec contain one literal six-field object copied from the published
decision. No envelope, alternate successor, override or environment binding is
allowed. Future implementation may cite only the exact two-field authorization
reference after this card is in `4.done` and the remote branch reaches the
published commit.

### 2. Dependency and block graph is closed

Authorization depends exactly on the investigation, integration decision,
scheduler v1 and v7 authorization and blocks only implementation v8. Future v8
uses the exact published dependency set required by the investigation:
installed-origin rescue v7, integration, scheduler v1, v6/v7 authorizations and
authorization v8; it blocks only certification.

### 3. Verification contract is inherited, not executed

Authorization normatively requires fresh pre-production RED and exact saved
tree reconstruction, exhaustive typed target inventory, closed binding and raw
execution ownership, source-level connected mutants, 35→30 profile,
four-stream bounds, scheduler-v1 and full-only authority. This docs-only card
does not create or execute any of those surfaces.

### 4. Dormancy is observable

Committable scope is limited to the card, same-slug artifacts, synchronized
main spec and archive metadata. Successor paths remain absent and production,
test and runtime LOC stay zero. Only static/current checks are admitted.
