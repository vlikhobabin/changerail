## Context

Affected v8 был clean-created от published authorization и дошёл до
deterministic preflight с валидной retained RED и зелёными allowed checks.
Preflight остановил review: generic bounded-authorization gate требует, чтобы
successor `Depends On` прямо содержал investigation id, но published v8
contract требует exact dependency set без
`investigate-affected-release-profile-contract-closure-boundary-v8`. Изменение
v8 card нарушило бы один из двух fail-closed contracts.

Latest safe source — published v8 authorization tip
`5b4981f92e55bec4644fef100171bb3e83f00cc1`. Unpublished v8 card, code, tests,
manifest, evidence и preflight runtime state не являются input; decision
переносит только bounded chronology и сам contract contradiction.

## Goals / Non-Goals

**Goals:**

- объявить executable v8 terminal и forensic-only без обхода preflight;
- определить clean v9 lineage с separately published authorization;
- сделать rescue investigation id прямой dependency implementation v9;
- сохранить bounded authorization ceiling и весь accumulated affected profile;
- удержать certification заблокированной до published v9 implementation.

**Non-Goals:**

- читать, исправлять, публиковать или воспроизводить terminal v8 payload;
- менять generic direct-investigation preflight или published v8 contract;
- создавать authorization/implementation v9 либо certification card;
- запускать history, real full/affected, benchmark, live matrix или
  certification checks;
- расширять affected authority, wire protocol или 499 production LOC ceiling.

## Decisions

### 1. V8 завершается как неприменимый executable contract

Decision сохраняет оба опубликованных fail-closed требования и не пытается
подстроить terminal v8 card. Допустима только concise chronology: clean start,
valid retained RED, green allowed checks, deterministic preflight contradiction
и отсутствие semantic review/publish.

Альтернатива — добавить investigation id в v8 `Depends On` — отклонена, потому
что нарушает published exact dependency set. Ослабить generic preflight также
нельзя: это превратило бы bounded investigation authorization в необязательную
prose lineage.

### 2. V9 authorization связывает один clean successor

Эта decision публикует six-field investigation authorization object для
`implement-bounded-affected-release-profile-v9`. Отдельная docs-only
authorization v9 зависит ровно от decision, integration decision, scheduler v1
и authorization v8 и блокирует только implementation v9.

Раздельный commit сохраняет reviewable authority boundary: implementation
card, tests и executable payload не существуют до remote publication
authorization v9.

### 3. Implementation v9 прямо зависит от investigation

Exact dependency set implementation v9 содержит эту rescue decision,
integration decision, scheduler v1, authorization v8 и authorization v9.
Таким образом generic direct-investigation check и lineage contract проверяют
один и тот же id; transitive dependency не используется как замена direct edge.

Альтернатива — снова перечислить исторические predecessors вместо rescue id —
отклонена, потому что воспроизводит v8 contradiction.

### 4. Accumulated affected contract переносится без расширения

Future v9 сохраняет retained pre-production RED, exact 35→30 profile,
exhaustive typed admission, effective package origins, strict four-stream Git
selection, typed scheduler, full-only authority, source-safe four-step CI,
closed execution ownership, connected source mutants и protocol-artifact
non-authority. Six-field object сохраняет ceiling `500`, что означает максимум
499 added production LOC, и protocol allowance без предоставления publication
authority affected mode.

## Risks / Trade-offs

- [Risk] Новая lineage добавляет ещё два docs/review этапа → mitigation:
  fail-closed authorization и direct edge проверяются до дорогой implementation.
- [Risk] Accumulated contract снова может стать слишком большим → mitigation:
  v9 меняет только dependency boundary и требует сохранить уже опубликованные
  requirements без нового executable scope.
- [Risk] `allow_new_authority_or_wire_protocol: true` может быть прочитан как
  authority grant → mitigation: full-release остаётся единственным publication
  authority, affected output и protocol artifacts остаются non-authoritative.
