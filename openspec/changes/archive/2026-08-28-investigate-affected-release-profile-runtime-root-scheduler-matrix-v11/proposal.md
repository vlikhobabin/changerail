## Why

Terminal unpublished affected-profile v10 exhausted its sole repair and still
left two connected boundary defects: runtime roots were admitted without an
exact dedicated-target proof, and scheduler proof completeness was inferred
from a catalog that could omit normative rows. Another executable patch would
repeat the defect class, so the clean lineage requires a published docs-only
investigation before any v11 authorization or implementation exists.

## What Changes

- Record the terminal v10 chronology and the forensic-only boundary without
  importing any terminal payload or runtime evidence.
- Define exact dedicated runtime-root admission and read-only per-task
  pre-reservation proof before Git, scheduler or filesystem mutation.
- Define a finite scheduler summary/result matrix whose valid neighbors and
  one-field invalid cases are independently enumerable from a normative
  requirement-to-row map and immutable reason schema.
- Freeze the only future order as investigation v11, separate docs-only
  authorization v11, clean implementation v11, then certification, with no
  more than 499 production LOC in the implementation.
- Keep this investigation dormant and docs-only with production, test and
  runtime LOC equal to zero.
