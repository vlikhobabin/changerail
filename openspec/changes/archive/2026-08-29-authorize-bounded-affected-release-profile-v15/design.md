## Decisions

### 1. Authority is one exact tracked object

The card and normative spec contain exactly:

```json
{"investigation_card":"openspec/board/4.done/investigate-affected-release-profile-origin-proof-discrimination-v15.md","investigation_id":"investigate-affected-release-profile-origin-proof-discrimination-v15","successor_card":"openspec/board/3.inprogress/implement-bounded-affected-release-profile-v15.md","successor_id":"implement-bounded-affected-release-profile-v15","production_loc_ceiling":500,"allow_new_authority_or_wire_protocol":true}
```

Extra keys, wrappers, alternate ids/paths, another successor or another ceiling
fail closed. The successor references only the published authorization through
the exact two-field object and starts from its publishing HEAD. Allowing the
investigation itself to authorize code is rejected because it bypasses the
separate reviewed authorization boundary.

### 2. Original RED is newly produced before executable mutation

The clean implementation may create only its card, same-slug OpenSpec and
focused-test artifacts before production, CI or main-spec mutation. The focused
test reaches a genuinely missing production module or symbol. Its direct
`bin/changerail-evidence capture` command first prints the current fingerprint
and then returns the genuine non-zero test exit without masking.

The retained failed entry binds raw missing-module/symbol output, exit code,
tree and diff fingerprint. The saved tree object exists before mutation and is
reconstructed relative to authorization HEAD. A later reproduction cannot
replace chronology.

### 3. Expected executable origin never comes from live PATH

Each token has one immutable typed descriptor. Repository targets resolve from
the exact repository root; Python equals real `sys.executable`; Ruff resolves
from the effective interpreter scripts root; Git/Node/npm/npx/bash use closed
source-authored per-platform targets or an independently admitted setup-toolchain
anchor. Live `PATH` is compared with the canonical target and never creates it.

Separate fake-first-`PATH` clean-child cases cover Python, Ruff, Git, Node, npm,
npx and the repository OpenSpec target. A usable exact-version fake remains an
origin fault before probes, Git, scheduler or mutation. Grouping by shared
anchor kind cannot substitute for any token case.

### 4. Proof separates data cases from uniquely counted semantic edits

Independent requirement and executable case catalogs have bidirectionally equal
ids. Every data case runs independently from its exact passing neighbor through
a public observer. Every claimed distinct mutant changes one semantic AST node,
operator or operand and retains its node path and canonical before/after digest
without marker nodes.

Several data cases may map to one semantic guard mutant, but that edit is
counted once. Reusing it under different labels, marker-only differences,
early-return weakening, no-op edits and earlier-fault masking do not count.

The scheduler oracle closes imports, assignments and calls and permits one
unaliased `run_plan` import plus one depth-one direct activation. Alias,
module-qualified, wrapper, `getattr`, dynamic, duplicate and alternate-entry
mutants fail public proof. Selector cases assert exact ordered tuples for every
stream/status and owner-distinct rename/copy operands, not membership floors.

### 5. Published floor remains additive and authorization remains dormant

V15 retains the published original-RED, Unicode `23/235`, exact 35-ID identity
and 35-to-30 ownership, aggregate admission, typed scheduler rows and bounded
failures, full-only authority, source-safe four-step CI, resolved-base guards
and protocol-artifact non-authority. Authorization changes documentation only;
executable successor surfaces remain absent until remote publication.

## Risks / Trade-offs

- **[Risk]** Shared platform anchors can hide omitted token cases. → The
  authorization enumerates every Python/Ruff/Git/Node/npm/npx/repo-OpenSpec
  clean-child case independently.
- **[Risk]** Many cases can inflate one guard edit into many mutants. → Case ids
  and distinct semantic mutant identities are separate catalogs; reused edits
  are counted once.
- **[Risk]** A docs-only authorization may be mistaken for affected authority.
  → It authorizes only one separately reviewed successor; affected artifacts
  remain non-authoritative.
