## Decisions

### 1. Authority is one exact tracked object

The card and normative spec contain exactly:

```json
{"investigation_card":"openspec/board/4.done/investigate-affected-release-profile-public-proof-closure-v16.md","investigation_id":"investigate-affected-release-profile-public-proof-closure-v16","successor_card":"openspec/board/3.inprogress/implement-bounded-affected-release-profile-v16.md","successor_id":"implement-bounded-affected-release-profile-v16","production_loc_ceiling":500,"allow_new_authority_or_wire_protocol":true}
```

Extra keys, wrappers, alternate ids/paths, another successor or another ceiling
fail closed. The successor references only the published authorization through
the exact two-field object and starts from its publishing HEAD. Allowing the
investigation itself to authorize code is rejected because it bypasses the
separate reviewed authorization boundary.

### 2. Original RED is newly produced before executable mutation

The clean implementation may create only its card, same-slug OpenSpec and
focused-test artifacts before production, CI or main-spec mutation. The focused
test reaches a genuinely missing production module or symbol. Its direct
`bin/changerail-evidence capture` command first prints the current fingerprint
and then returns the genuine non-zero test exit without masking.

The retained failed entry binds raw missing-module/symbol output, exit code,
tree and diff fingerprint. The saved tree object exists before mutation and is
reconstructed relative to authorization HEAD. A later reproduction cannot
replace chronology.

### 3. One registry and independent ledgers close pre-Git admission

One immutable physical-task registry owns literal argv, typed operands, origin
descriptors, logical IDs and owners. Separate extractors compare literal and
embedded operands bidirectionally with this registry; live runtime discovery
cannot become expected truth. Admission proves repository, origins and packages,
then dedicated runtime and selected task roots, before Git, plan or scheduler.

Python audit/profile hooks and filesystem snapshots independently observe probe,
process, Git, scheduler and mutation effects. A fake-first clean child therefore
cannot satisfy its own oracle or touch a later ledger.

### 4. Public protocol boundaries carry exhaustive proof

The selector exposes pure framing/ownership and real-Git collection boundaries.
Disposable repositories produce actual committed, staged, unstaged and
untracked streams, including owner-distinct A/M/D and rename/copy tuples,
without replacing `_run_git`.

The scheduler summary validator is a public pure trust boundary. Independent
requirement, case and semantic-mutant maps have equal IDs and cover every
reason/top-level field neighbor with exact canonical AST paths and digests.

### 5. Closed execution ownership forbids hidden alternates

The ownership oracle parses runner, profile, scheduler and broker together. It
freezes imports, bindings, calls and raw execution sites, and rejects alias,
rebind, wrapper, `getattr`, dynamic, duplicate, alternate, subprocess,
`os.system`, `exec` or `eval` sites outside the graph.

### 6. Published floor remains additive and authorization remains dormant

V16 retains published Unicode `23/235`, exact 35-ID identity and 35-to-30
ownership, aggregate admission, typed scheduler rows and bounded failures,
full-only authority, source-safe four-step CI, resolved-base guards and
protocol-artifact non-authority. Authorization changes documentation only;
executable successor surfaces remain absent until remote publication.

## Risks / Trade-offs

- **[Risk]** A unified registry can still self-certify through shared extractors.
  → Independent literal/embedded extraction and bidirectional comparison remain
  mandatory.
- **[Risk]** Public cases can use synthetic Git rows. → Selector proof must
  create disposable repositories and run real public collection.
- **[Risk]** A closed graph can miss dynamic execution. → Raw execution-site
  inventory rejects every site outside the frozen four-module graph.
- **[Risk]** A docs-only authorization may be mistaken for affected authority.
  → It authorizes only one separately reviewed successor; affected artifacts
  remain non-authoritative.
