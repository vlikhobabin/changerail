## Decisions

### 1. Hosted proof has a closed source-safe setup-node anchor

The future proof first parses the exact canonical four-step CI source and
requires the published checkout/setup-node action pins, `node-version: "20"`,
absence of workflow/job/step environment overrides and the exact full-release
step. That parsed source, not live `PATH` or production metadata, selects the
hosted-origin grammar.

The hosted grammar admits only one real absolute `RUNNER_TOOL_CACHE` root and
the setup-node Linux layout
`node/<20.x.y>/<arch>/bin`. It requires exactly one closed SemVer `20.x.y`
directory for the independently supplied architecture. `node` is the exact
regular executable entry. `npm` and `npx` are exact bin entries whose bounded
relative symlink/launcher resolution stays inside the same version subtree and
ends at their published npm CLI target shape. Absolute links, traversal,
multiple versions/architectures, another major, another token or any escape
fail before usability probing.

This deliberately differs from the local `_SYSTEM_ORIGINS` branch. Hosted
admission must identify its exact grammar and selected canonical target from
the parsed CI contract plus environment/filesystem observation. Local system
tables remain a separate fallback only outside declared hosted context; they
cannot satisfy a hosted case.

Alternative rejected: accepting `which node` followed by a successful version
probe. A fake executable can satisfy both. Alternative rejected: trusting a
production `origin_kind` or branch ledger. That only restates the candidate's
decision.

### 2. Each Node-family token gets an actual clean-child hosted witness

Future focused proof owns separate `node`, `npm` and `npx` clean-child cases.
Before production import, the harness creates a disposable source-safe
setup-node-shaped root, supplies `RUNNER_TOOL_CACHE` and architecture, and puts
an exact-version successful fake for the selected token first in `PATH`. The
fixture layout and expected final target are authored by the proof oracle from
the closed grammar, never imported from production descriptors.

Pre-import audit/profile hooks and an external process observer record the
actual executable target and argv. The case passes only if production selects
the oracle's exact toolcache target, the relevant origin-admission branch is
reached, the fake marker stays absent and later behavior is the bounded
expected probe/admission result. A production branch marker can be retained as
diagnostic only; it cannot satisfy the oracle.

Negative neighbors cover missing, relative, symlinked or outside-root
`RUNNER_TOOL_CACHE`; wrong/duplicate version or architecture directories;
wrong token; broken/escaping launcher links; zero/multiple canonical targets;
fake-first usable PATH; and attempted hosted-to-system fallback. Each failure
must occur before Git, plan, scheduler or write intent and is checked through
external event/snapshot observation.

The cases are source-safe simulations of the pinned hosted layout. They do not
run a live matrix and do not authorize publication. Certification remains the
only later critical gate allowed to use its bounded final execution budget.

### 3. The activation observer is distinct from `ACTIVATION_CATALOG`

Future proof implements an independently authored deterministic AST/source
observer. It does not import production registry/extraction, catalog builder or
expected sets. It parses exact affected runner/profile source plus exact-digest
published scheduler/broker source and records the complete syntax inventory of
imports, bindings, functions, predicates, calls and raw sinks.

The observer then runs a finite context-sensitive worklist seeded only by the
public affected entrypoint and the exact production argument row, including
the exact task rows, jobs and `supervisor=None`. Context identity contains the
qualified callable plus canonical bound arguments and predicate facts. Import
aliases, local assignments, parameters, exact member receivers and return
bindings are propagated only through allowlisted finite rules. Callable
parameters, ambiguous/empty sets, runtime rebinding, dynamic lookup, wrappers
or unknown call forms fail closed rather than widen to `Any`.

For every syntactic item the observer materializes one canonical row with:

- stable item ID and kind;
- repository-relative source path and whole-source digest;
- qualified owner and canonical AST field/index path;
- normalized context and predicate facts;
- exact finite callee/receiver set where applicable;
- exact reachable or latent classification;
- exact argument-backed unreachable reason or raw-sink classification.

Observed rows are produced solely from parsed source and the seed arguments.
`ACTIVATION_CATALOG` is authored separately as immutable test data. Full row
sets, field values and identities compare as canonical multisets in both
directions. A length/uniqueness check is only an initial structural check and
cannot establish equality. Extra observed rows, unused catalog rows, changed
context/argument/predicate/callee data or a classification transition all
fail.

Alternative rejected: generate the catalog from observer output. That makes
source drift self-certifying. Alternative rejected: compare only reachable
edge counts. That omits latent injected callbacks and raw sinks.

### 4. Reachable static rows require an external dynamic witness

A separate clean child installs profile/audit hooks before importing the public
runner. It invokes the exact public affected activation with the admitted
production argument row and observes qualified Python call edges, scheduler
entry arguments and raw process sinks without replacing production functions,
constants, calls or results.

The dynamic trace's canonical reachable edge/sink projection must equal the
static observer's reachable projection after explicitly excluding interpreter
and proof-harness frames. The exact default path must be
affected entrypoint → profile/runner → published scheduler default → published
broker sinks. The scheduler injection callback remains present in syntax and
catalog, but its `supervisor is not None` predicate is false under the seed and
therefore it is an exact latent row. A non-None supervisor, alternate wrapper,
unlisted sink or reachable row without a trace witness fails.

Absence from a trace alone never proves unreachable. Every latent catalog row
must have an observer-produced predicate/argument-backed reason, and every
reachable static row must have its dynamic witness. This joins the structural
and behavioral halves without trusting production ledgers.

## Risks / Trade-offs

- **[Risk] Disposable toolcache is mistaken for live GitHub proof.** The
  contract labels it source-safe focused evidence only and keeps live/certified
  authority out of this lineage stage.
- **[Risk] npm/npx launcher layout varies.** The hosted grammar is intentionally
  closed to the parsed canonical setup-node/Linux contract; an unknown layout
  fails and requires a new published decision instead of runtime inference.
- **[Risk] Static interpretation becomes another catalog.** The observer is an
  executable source-derived worklist with complete row materialization;
  catalog authoring is separate and full row equality is bidirectional.
- **[Risk] Dynamic tracing misses an optimized or C-level edge.** Raw sinks are
  also captured by audit hooks and every expected reachable static sink must
  have an explicit observed witness; uncertainty fails closed.
- **[Risk] Proof scope exceeds the 499-line production ceiling.** Proof code is
  test-only and production remains bounded; authorization preflight rejects an
  over-ceiling successor.
