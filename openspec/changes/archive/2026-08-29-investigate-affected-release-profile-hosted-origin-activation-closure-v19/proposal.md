## Why

Terminal unpublished affected-profile implementation v18 исчерпал repair
budget после fresh `NO-GO`: proof не запускал canonical hosted
setup-node/`RUNNER_TOOL_CACHE` origin branch и не строил observed
context-sensitive activation graph для сравнения с independently authored
catalog. Новый executable patch запрещён, пока эти два повторившихся proof
инварианта не закрыты clean published design decision.

## What Changes

- Зафиксировать source-safe clean-child proof для hosted `node`, `npm` и `npx`,
  который независимо выводит expected targets из pinned CI/setup-node contract,
  действительно проходит `RUNNER_TOOL_CACHE` branch и наблюдает actual process
  targets при fake-first `PATH`.
- Зафиксировать deterministic source interpreter, который от exact affected
  entrypoint и argument row материализует complete context-sensitive activation
  graph, и bidirectionally сравнить observed rows с отдельным immutable catalog.
- Связать reachable static projection с independent pre-import profile/audit
  trace, сохранив injected supervisor path cataloged but unreachable при
  `supervisor=None`.
- Заморозить clean порядок v19: эта investigation, отдельная docs-only
  authorization, чистая implementation с новым original RED, затем final
  certification.
- Сохранить published v18 proof inventory, accumulated affected floor и
  full-release-only publication authority без executable mutation.
