## Why

Terminal clean implementation v17 сохранил три blocker-class после
единственного repair: scheduler proof оставался self-derived, structural
execution/resolved-base proof допускал dynamic bypasses и disconnected mutants,
а registry/ledger proof сравнивал согласованные literals и production-declared
empty observations. После повторения этих инвариантов новая executable попытка
без отдельного design decision запрещена.

## What Changes

- Зафиксировать четыре независимо authored scheduler catalog и closed mutation
  language с pinned canonical AST anchors, source/digest identity и
  reachability-before-divergence kill proof.
- Зафиксировать partitioned whitelist structural resolver: strict direct graph
  для affected-owned source и exact-digest legacy graph для immutable
  published scheduler/broker, где higher-order shapes допустимы только при
  finite unique static binding.
- Потребовать connected source mutant и public explicit-root case для каждого
  resolved-base, collector и fallback guard.
- Разделить independently published authorization-time command/typed-operand
  digest, production registry/extraction и proof direct/embedded parser.
- Заменить production-declared ledgers на clean-child audit/profile events и
  external filesystem snapshots.
- Заморозить exact v18 authorization/implementation lineage, ceiling `500`
  (`499` added production LOC) и новый original-RED boundary без создания
  successor artifacts.

## Capabilities

### Modified Capabilities

## Impact

Изменяются только board card, same-slug OpenSpec artifacts, synchronized
`openspec/specs/changerail-release-ci/spec.md` и archive metadata. Production,
tests, CI, runtime state, authorization v18, implementation v18 и certification
не создаются; consumer execution и publication authority не меняются.
