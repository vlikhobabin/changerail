## Context

Terminal unpublished v16 сохранил большую часть bounded affected-profile floor,
но fresh review cycle 2 обнаружил два residual proof defects. Pure parser
проверял `R/C 000`, однако disposable real-Git layer не мог показать этот score;
попытка потребовать невозможную emission стимулирует synthetic masquerading.
Scheduler proof, напротив, заставлял иметь mutant на каждый data case и получил
payload-specific early returns вместо независимых semantic guard edits.

Игнорируемый disposable diagnostic подтвердил границу Git: полностью несходные
delete/add pairs остаются `D` + `A` даже при нулевом rename/copy threshold, а не
становятся `R000/C000`. Это наблюдение не является release/certification
evidence и не входит в tracked payload.

## Goals / Non-Goals

**Goals:**

- сделать selector proof честным относительно public grammar и реального Git;
- определить конечную guard-relative scheduler completeness relation;
- запретить generated bypass mutants структурно, а не reviewer convention;
- сохранить clean lineage, bounded LOC и весь уже закрытый release floor.

**Non-Goals:**

- не реализовывать profile, tests, CI или runtime protocol;
- не ослаблять acceptance `R/C 000` как допустимой public grammar;
- не запускать real full/affected release, history, benchmark, live matrix или
  certification;
- не читать и не переносить terminal v16 executable artifacts/evidence.

## Decisions

### 1. Разделить score grammar и Git emission

Public pure NUL framing/ownership boundary остаётся authoritative oracle для
всего syntactically valid диапазона `000..100`: она обязана потребить оба
old/new operand и получить exact owner-ordered selection. Public real-Git
collector проверяется отдельными disposable repositories на A/M/D, четырёх
streams, owner discrimination и emitted non-zero rename/copy scores, включая
interior и `100`.

`R/C 000` не фабрикуется через monkeypatch, wrapper или подмену command output.
Если Git не распознаёт пару как rename/copy, collector обязан сохранить честный
`A/D` outcome. Альтернатива «заставить Git вернуть R000» отвергнута как
непереносимая и не наблюдаемая public boundary.

### 2. Сделать guard ID единицей semantic mutation

Три каталога authored независимо:

- requirement guard catalog: normative guard IDs и canonical node selectors;
- executable case catalog: unique case IDs, passing neighbor, single changed
  field/invariant и exact `guard_id`;
- mutant catalog: ровно один genuine AST operator/operand edit на `guard_id`.

Инвариант completeness:

`requirement_guard_ids == mutant_guard_ids == referenced_case_guard_ids`.

Case IDs имеют отдельную equality только с normative case inventory. Несколько
case IDs могут ссылаться на один guard, но каждый case выполняется независимо,
а каждый guard имеет хотя бы один exact passing/invalid neighbor. Альтернатива
`case_ids == mutant_ids` отвергнута: она считает data cardinality semantic
cardinality и поощряет duplicate edits.

### 3. Ограничить mutation language

Mutator может заменить только существующий canonical AST operator или operand
по exact node path. Он не может добавлять `return`, `raise`, payload predicate,
marker, new guard или новый control-flow node. Before/after digest вычисляется
из canonical AST без location/test metadata. Every mutant выполняется через
public scheduler-summary boundary и обязан изменить outcome своего mapped
neighbor; node path и digest pair уникальны между guard IDs.

### 4. Продолжить только через clean docs-only authorization

После публикации investigation создаётся отдельная authorization v17, затем
clean implementation v17 от authorization HEAD, затем единственная final
certification. Terminal v16 остаётся forensic-only. Implementation ceiling
остаётся `499` added production LOC; affected mode остаётся permanently
non-authoritative.

## Risks / Trade-offs

- [Git может emit-ить разные non-zero scores на разных версиях] → fixture
  утверждает semantic class/range и exact observed operands, а не выдуманный
  невозможный `000`; pure boundary закрывает полный grammar диапазон.
- [Many-to-one case mapping может скрыть missing case] → separate normative
  case inventory сравнивается bidirectionally с executable case IDs, а guard
  relation проверяется вторым независимым invariant.
- [AST node path хрупок к refactor] → path принадлежит published proof contract;
  любое изменение требует осознанного catalog update и fresh review.
- [Новый lineage увеличивает roadmap] → docs-only investigation/authorization
  дешевле ещё одной terminal implementation и устраняет две противоречивые
  предпосылки до coding.

## Migration Plan

1. Опубликовать эту docs-only decision.
2. Опубликовать exact authorization v17 с тем же proof contract.
3. Создать implementation v17 clean от authorization-publishing HEAD и новый
   retained original RED до executable mutation.
4. После fresh implementation GO выполнить единственную final certification.

Rollback не нужен: investigation не меняет executable surface. Если review
отклоняет design, authorization и implementation не создаются.

## Open Questions

Нет. Git grammar/emission и case/guard/mutant cardinality разрешены этой
