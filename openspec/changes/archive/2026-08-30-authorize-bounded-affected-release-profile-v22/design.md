### 3. Additive admission terminates in atomic descriptor-bound execution

Legacy scheduler v1 `run_plan`, broker v5 `supervise`, their inputs/defaults,
result tuples and authority-free semantics remain compatible. V22 adds only
`changerail.release-admitted-execution.v1`: an exact ordered one-to-one table
whose direct row contains one member and whose composite row contains one outer
group executor plus every exact ordered inner member.

Each direct/outer/inner record commits owner/member identity, exact logical
argv, deterministic physical argv/FD map, complete executable/operand
component identities, closed environment and canonical digest. The scheduler
validates the complete table before workers, opens every object with no-follow
descriptor operations, seals the nested table in a bounded Linux `memfd` and
retains exact executable/operand FDs.

The additive broker wraps the published bounded capture/cleanup/result
semantics around a fork/pipe adapter whose child calls FD-capable
`os.execve(fd, argv, env)` on the already-verified native executable FD. A
close-on-exec status pipe distinguishes successful exec from bounded pre-start
failure. Scripts and launchers use a pinned native interpreter FD and pinned
`/proc/self/fd/<n>` operand references, never kernel shebang, `/usr/bin/env`,
live PATH or path reopening.

Composite work remains one scheduler task/result. The admitted group executor
receives only owner ID, registry/admission digests and sealed-bundle FD,
validates every inherited member FD and invokes the additive broker in exact
order; first failure starts zero later members.

Alternatives rejected: clearing global environment, a wrapper target,
path-based Popen after revalidation or result-schema authority. Each retains an
ambient or check/use gap and is unnecessary for the closed result contract.

### 4. The execution oracle is independent of production admission

The oracle derives every direct/outer/inner logical and physical row from the
immutable inventory, pinned CI and fixture filesystem. It observes exec audit/
syscall inputs, `fstat` identities, sealed bundle and post-exec `/proc` target,
not a production branch marker. It separately proves that admitted work never
reaches legacy Popen.

The matrix changes every environment/member/bundle/digest, places a usable
fake first in PATH, swaps targets before open, renames paths after open and
exercises missing/extra/reordered/cross-owner/malformed records. Unadmitted
targets must not start; a post-open rename must still execute the opened object.

### 5. Every syntax row receives a public-seeded worklist result

The observer independently enumerates every import, binding, function,
predicate, call and raw sink in exact runner/profile/group-executor/admitted-
transport and exact-digest scheduler/broker sources. Canonical row identity

One finite worklist starts only at public

A separately authored immutable `ACTIVATION_CATALOG` lists all fields for all
rows. Observed syntax, worklist result and catalog compare bidirectionally.
Empty/sentinel annotations, self-derived rows, ambiguous binding, runtime
rebind, alternate wrapper/sink or latent transition fail.

### 6. Raw events prove one exact normalized topology

Before production import, the disposable child installs test-only
`sitecustomize`, nonce-bound bounded Unix datagram collector, import guard,
opcode/profile/audit hooks and at-fork registration. Public, scheduler-spawn
and group-executor processes must register before production events with closed
roles, source digests, sequence and pid/ppid/spawn/fork/exec topology.

Every raw production occurrence is retained and maps uniquely to one catalog
row. Only repeated iterations sharing exact `(role, row, normalized context,
predicate facts, callee/receiver)` may collapse. The normalized dynamic
multiset, static reachable projection and catalog reachable projection compare
exactly and bidirectionally through public affected, admitted scheduler,
descriptor-bound broker, group executor and ordered inner brokers.

Test transport never counts as a production row, pass, authority or proof of
unreachability. Loss, overflow, missing/late/bad-nonce registration, sequence
gap, disconnected parentage, unmapped event, extra key or alternate sink fails.

### 7. Runtime admission proves ancestry from one exact anchor

Phase A accepts only one lexically exact direct child of one real runtime
anchor. Starting from the opened anchor FD it walks every component with
`O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, compares lexical/real spelling and
`(device,inode,type,mount)` identity, and rejects repetition, symlink, alias,
mount or outside-anchor transition.

The candidate is a real empty directory, and the same FD chain/emptiness is
rechecked immediately before scheduler reservation. Any neighbor, dangling
entry, non-directory or identity drift produces bounded non-authoritative
`semantic_started:0` with zero later process, Git, scheduler, write or mutation

## Risks / Trade-offs

- **[Risk] Additive transport changes published scheduler/broker source.** The
  authorization names only this bounded surface; compatibility and dormancy
  proofs preserve legacy entrypoints and result schema.
- **[Risk] Descriptor identity is runtime-specific.** Runtime rows remain
  ephemeral evidence, never tracked inventory or authority.
- **[Risk] Catalog/topology proof is large.** Canonical row identity,
  forbidden sentinels and bidirectional equality make completeness mechanical.
- **[Risk] Timing loops vary.** Every raw occurrence is retained; only exact
  activation-key repeats normalize under finite row bounds.
- **[Risk] The 499 LOC ceiling is tight.** The successor must reuse published
  validation, scheduling and broker cleanup primitives; preflight rejects
  over-ceiling payloads.
