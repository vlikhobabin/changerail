## Why

Terminal unpublished implementation v21 proved that origin admission without
an environment/executable-bearing broker boundary does not constrain the
process actually started, while placeholder catalog annotations and an
incomplete dynamic oracle cannot prove the public activation graph. The same
attempt also exposed incomplete runtime ancestry validation and irreversibly
entered a prohibited fallback diagnostic, so a clean published decision is
required before any executable successor.

## What Changes

- Authorize a narrowly additive admitted-execution transport that binds each
  scheduler owner and every composite member to exact logical argv, executable/
  operand FDs and closed environment at an atomic FD-capable `os.execve`
  boundary
  while retaining the published entrypoints.
- Replace counts/placeholders with a fully annotated row-level context worklist
  and separately authored immutable catalog.
- Define complete raw-event mapping and exact normalized equality among static,
  catalog and dynamic activation topology from the public affected entrypoint.
- Define a directory-FD, no-follow ancestry walk from an exact runtime anchor
  through the empty candidate root.
- Require a new original-RED and disposable focused episode that cannot invoke
  workspace full fallback, history, live or certification surfaces.
- Preserve the immutable v18 inventory and all accumulated selection,
  non-authority and certification boundaries.

## Impact

This change is docs-only. It affects one board card, same-slug OpenSpec
artifacts and the accumulated release-CI specification. It adds no production,
test or runtime behavior, does not import terminal v21 payload/evidence and
does not run history, real full/affected, live or certification evidence.
